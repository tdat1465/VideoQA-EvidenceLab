# Subtitle-guided multi-anchor frame selection (development snapshot)

This records the code used for the 2026-11 LongVideoBench validation experiments. The selector starts from **event coverage on RIDGE σ2**, not plain RIDGE. It extracts public query text from the question or all multiple-choice options, matches time-stamped subtitle cues, retains up to three separated matches per query, inserts at most 16 frames around those matches, and fills the remaining frame budget from the event-coverage selection. No correct-answer label is used to select frames. Subtitles are used by the selector and are not passed as text to the answer model.

`src/evidencelab/subtitle_anchors.py` exposes the frozen matching and selection rules as standalone functions. `prepare_full.py` and `run_pilot.py` are the original experiment scripts; they have **not** been refactored to call that module. Tests compare the standalone functions with the original source so that the refactor can be audited. Keep the original snapshot for provenance.

## Source and outputs

- `prepare_full.py`: full-run subtitle parsing, anchor plan and five-worker launcher.
- `run_pilot.py`: Molmo2 event-coverage, one-anchor and multi-anchor branches, fixed frame count per example and exact fallback. The full branch reuses the preceding event-coverage prediction when the frames match.
- `relational/`: the five-worker σ2 event-coverage code and its canonical frame helper required by the original scripts. The other relational variants are retained because they were present in the source run; they did not improve accuracy in the prior evaluation.
- `backbones/`: frozen Qwen2.5-VL, LLaVA-OneVision and split InternVL workers, InternVL split supervisor, and paired analysis. Qwen uses 224×224 pixels per frame. The later InternVL split changes attention to SDPA and chunks its MLP to fit five workers; its pilot was checked on 10 records per machine, not for exact numerical parity against eager attention on every case.

The scripts are **research snapshots**, not a one-command installation: they were executed in Molab under `/marimo/ridge-canonical`, with a checkout at `repo-fresh` and the relational helper directory at `relational-w5-v1`. The source revision of the canonical selection run is `e3e3cad9a0d80f31a5dee47e837df3bf44db77c3`. They depend on pinned inputs, downloaded gated LongVideoBench annotations/videos/subtitles, model revisions, the event-coverage predictions and canonical pixel reference manifests. Those inputs, credentials, model weights, logs, results and checkpoint archives are intentionally not in Git. `prepare_full.py` expects the subtitle archive and annotations locally; it also launches workers as soon as the plan is ready.

The multi-backbone scripts additionally expect a paired manifest containing both `frame_indices` (RIDGE σ2) and `multi_frames`, and canonical reference metadata. The paired manifest is an experiment artifact, not generated by the standalone selector automatically. The provided snapshot does not include an end-to-end bootstrap for those prerequisites, and should not be presented as a fully self-contained reproduction package. The original JSONL resume logic has no complete source/model/runtime contract; verify configuration, data, frame sets and dependencies before resuming in another runtime.

The historical Molmo2 pipeline used 1,337 validation questions, three arms, a maximum of 64 frames and five workers. In the later paired backbone comparison, RIDGE σ2 is compared against the **combined** event-coverage-plus-subtitle method, so the difference cannot be attributed to subtitles alone. LongVideoBench validation was inspected during development; do not treat the observed gains as an independent test. Resume across runtimes matched ten pilot records, which does not prove all runtime behavior is identical. Canonical base-frame hashes were checked, but the new subtitle-guided frames have not been independently replayed against an earlier pixel manifest.

## Quick use of the selector

```python
from evidencelab.subtitle_anchors import candidates, queries, select, windows

query_texts = queries(question, choices, question_type)
spans = list(windows(subtitle_cues))
record = {
    "offset": subtitle_offset_seconds,
    "matches": [{"candidates": candidates(query, spans)} for query in query_texts],
}
frame_indices = select(eventcover_frame_indices, source_frame_count, fps, record, limit=3)
```

`select` returns source-frame indices in chronological order and preserves the baseline frame count. Inputs are the original source frame count/fps, not indices into a subsampled candidate grid. `limit=1` reproduces the one-anchor control; `limit=3` reproduces multi-anchor. If no valid match exists, the baseline is returned. This API assumes valid, unique baseline frame indices and a positive FPS, as did the experimental source.

Run the source-parity tests with `python -m unittest discover -s tests -p test_subtitle_anchors.py` after installing the repository package or setting `PYTHONPATH=src`.
